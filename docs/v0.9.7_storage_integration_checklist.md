# OLRE v0.9.7 Storage Integration Implementation Checklist

Date: `2026-05-10`  
Branch: `hardening/storage-integration-and-operational-qa`  
Target Tag: `v0.9.7-storage-integration`

## Objective

Complete the transition from partial direct filesystem handling to centrally auditable storage execution, while preserving operational behavior.

## Guardrails

- Keep `LocalStorageService` as a thin facade
- Keep policy in service layer
- Keep execution in storage layer
- Preserve processing semantics during refactor
- Prefer `storage_key` over path for retained artifacts
- Maintain compatibility-first migration behavior
- Treat cleanup as high-risk infrastructure

## Workstream 1. Storage Module Decomposition

- Create internal storage modules:
- `app/storage/document_storage.py`
- `app/storage/export_storage.py`
- `app/storage/debug_storage.py`
- `app/storage/temp_storage.py`
- `app/storage/path_resolver.py`
- Keep `LocalStorageService` as a thin facade over these modules
- Preserve public imports from `app/storage/__init__.py`
- Avoid inheritance-heavy or generic artifact frameworks

## Workstream 2. Batch / Retry Integration

- Refactor retained source save/read/delete calls in `app/services/process_batch.py`
- Replace direct temp-file copy/delete with `temp_storage` calls
- Refactor `app/services/retry_service.py` to read retained source via `storage_key` first
- Keep fallback support for legacy `last_source_path`
- Preserve retry semantics, fingerprint timing, and extraction ordering

## Workstream 3. Retention / Cleanup Hardening

- Refactor `app/services/retention_service.py` to remove raw `Path`, `glob`, `unlink`, and `stat` usage
- Implement deterministic cleanup flow:
- discover candidates
- validate lifecycle safety
- validate not-processing
- validate reference safety
- dry-run summary
- execute deletion
- structured deletion report
- Add lightweight structured logging for cleanup outcomes
- Keep cleanup behavior conservative and deterministic

## Workstream 4. Route / Debug Boundary Cleanup

- Refactor inbox upload/delete in `app/web/routes_operations.py`
- Move inbox file write/delete operations into storage layer
- Refactor `app/batch/qr_debug.py` to use `debug_storage`
- Ensure `app/web/routes_debug.py` consumes debug payloads through storage-backed API only
- Prevent path resolver leakage into route/business logic

## Workstream 5. Compatibility and Lifecycle Stabilization

- Write both legacy path fields and `storage_key` where required
- Read prefer `storage_key`
- Fallback legacy path for existing rows
- Preserve `moved_to_path`, `last_source_path`, and `source_file_path` during this phase
- Keep lifecycle transitions correct for:
- processed
- failed
- retained
- deleted
- retry-available
- retry-requires-reupload

## Workstream 6. Operational QA

- Verify batch ingestion still passes
- Verify duplicate/cached-source flows still pass
- Verify retained failed-source cleanup is deterministic
- Verify retry from retained source still works
- Verify upload/import flows still work
- Verify debug artifact flows still work
- Verify export generation remains operational
- Verify no filesystem regressions leak back into service/route layers

## Validation Commands

- `uv run ruff check app tests migrations`
- `uv run pytest`
- targeted verification for:
- `tests/integration/test_batch_flow.py`
- `tests/integration/test_retry_flow.py`
- `tests/integration/test_qr_debug_flow.py`
- `tests/integration/test_storage_hardening.py`
- `tests/integration/test_ui_flow.py`

## Completion Criteria

- Business logic no longer manipulates filesystem paths directly
- `storage_key` is the preferred artifact identity
- Cleanup behavior is deterministic and auditable
- Retry flows remain operational
- Lifecycle transitions remain correct
- Operational visibility improves with structured logs/reports
- No functional regressions are introduced

## Final Deliverables

- updated storage integration code
- passing QA verification
- production-grade changelog / handoff document for v0.9.7
